# UX and workflow review — 2026-09-05

Scope: current working tree on `claude/monetization-m1`, including existing uncommitted changes. This is a code review, not browser confirmation or a merge approval. Existing user changes are preserved. Implementation awaits the AGENTS.md plan gate.

## Findings

### 1. P1 — Visible identity differs from the authenticated actor

`lib/client/session-context.tsx:160-164` selects the requested persona and then calls `setRoleKey`. `components/jeeves/role-context.tsx:108-109` implements that call by selecting the role's representative persona. Logging in as Marcus Webb therefore leaves the authenticated session as Marcus but shows Elena Vasquez and Clinical Safety in the role context. The same issue affects the second requester. Reloading also resets the role context to Program Office while retaining the live session.

The review queue and agent-run eligibility use the displayed domain; mutations use the session identity. Users see the wrong assignments or action availability. The visible role switcher can independently recreate this mismatch.

Fix: make the authenticated persona authoritative in live mode, retain preview switching in public mode with explicit labeling, and rehydrate the exact persona. Test every persona, reload, and public/live transitions. Existing login coverage only exercises the representative reviewer.

### 2. P1 — Switching intake modes loses unsaved work

`components/jeeves/intake-mode-toggle.tsx:21-25` mounts each intake UI inside a panel without `keepMounted`. `components/ui/tabs.tsx` passes through to the installed Base UI panel, whose default is `keepMounted = false`; inactive children unmount. Both the form and chat hold their draft locally.

Entering a form, trying the chat tab, and returning resets the form. The reverse loses the conversation. Preserve both drafts across mode changes and test round trips, including an in-flight chat response. Explain whether modes share one draft or retain separate drafts.

### 3. P1 — Retrying intake submission creates another draft

`components/jeeves/intake-form.tsx:300-329` always creates an initiative before submitting it. If creation succeeds and submission fails, the form shows an error but retains no created-record state for retry. Clicking Submit again creates another initiative; the service generates a fresh ID and slug on every create (`lib/services/initiative-service.ts:310-311`).

Preserve the successful creation result and offer retry against that same record. Freeze the submitted payload while pending and give a persistent recovery message/link. Test successful create followed by failed submit and successful retry, asserting one create call. A lost response to the create request itself needs a separate server idempotency design; a client-only fix cannot guarantee recovery from that case.

### 4. P1 — Draft failures and polling timeouts are reported as success

`components/jeeves/reviews-tab.tsx:88-100` treats every non-pending row as completed and also enters the success branch at the polling limit. Failed drafts therefore count as done, and still-pending drafts can produce “Draft run finished — drafts are ready for review.”

Distinguish successful drafts, partial failures, and unknown completion after timeout. Keep per-domain outcomes visible and provide an explicit refresh/retry action. Test mixed success/failure, missing requested rows, timeout, and polling errors. Refresh/reconnect must not automatically start another paid agent run.

### 5. P1 — A manual pause is presented as an eval breach

`app/(console)/initiatives/[slug]/page.tsx:106-116` and `components/jeeves/initiative-blockers-rail.tsx:20-21` infer an eval-quality breach from lifecycle state alone. The detail banner also asserts that a reassessment cycle is open. However, `lib/services/admin-service.ts:303-340` supports a manual pause with an arbitrary reason without creating that incident or review cycle.

Render a neutral paused status unless incident evidence establishes the cause; show the recorded reason/cycle only when available. Test a manual pause separately from the monitor-triggered breach. A governance product must not manufacture incident evidence from a status label.

### 6. P2 — Review selection is inaccessible from the keyboard

`components/jeeves/review-workbench.tsx:183-217` makes table rows clickable without a focusable selection control or keyboard activation. The selection opens the assessment workbench, so keyboard users cannot reach the central review flow from that queue.

Add a real named button in each row to open its review, expose selection state, and manage focus into the assessment. Also group each intake Yes/No pair under its question with a fieldset/legend (`components/jeeves/intake-form.tsx:652-681`), rather than leaving six repeated pairs labeled only Yes and No. Test keyboard activation and accessible question names.

### 7. P2 — Global search is an inert control

`components/jeeves/app-topbar.tsx:25-33` renders a search input with no query state, submission handler, navigation, or results. It promises searches across initiatives, controls, and decisions but typing has no effect.

Replace it with a working, accurately labeled initiative search backed by viewer-scoped data, with keyboard navigation and an empty-results state. Do not promise control/decision search until implemented. Test query matching, result navigation, no matches, and workspace isolation.

### 8. P2 — Case-file tabs do not preserve their location

`app/(console)/initiatives/[slug]/page.tsx:123` uses the URL only as an initial tab value. Tab clicks do not update it. Refresh and copied links therefore reopen an older/default tab, and Back cannot retrace tab navigation.

Make the selected tab follow a validated URL query parameter, retaining the existing legacy `operate` mapping. Test click, reload, copied link, and Back/Forward. Keep mobile tab sizing and keyboard focus in the browser verification pass.
